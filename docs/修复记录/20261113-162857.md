- 主题：2.2 测试环境接地——从知识库项目层环境文档逐字提取地址与账号（新开关 --test-env，默认关）

## 背景

2.2 测试环境此前口径为「凭证涉敏、长期人工填写」。实际团队已把环境地址与
账号密码维护在飞书知识库项目层文档（如 UniResearch项目测试 → UniResearch 相关
账号及说明文档 → Uniresearch测试环境及账号，正文为「环境名 / http 地址 / 账号密码」
行组）。经用户 2026-11-13 拍板：口径反转，凭证逐字写入报告 2.2（报告与源文档
同处知识库权限体系，敏感度不升级），来源文档标注在表后。

## 变更内容

- 新模块 `report_agent/report/test_env.py`：
  - `parse_env_rows`：严格行组解析——环境名须与表行名全等、地址须 http(s) 开头、
    凭证非空且不是下一个环境名，三件齐备才采纳（宁缺毋滥，不做模糊猜测提取）；
  - `collect_env_candidates`：项目节点层检索（标题含关键词的 docx，深度 ≤2，
    跳过版本目录不下探，沿用 find_doc_urls 逐层收窄不兜底红线）；
  - `resolve_test_env`：逐份读正文、第一份解析出 ≥1 行的即采纳（单源采纳不跨文档
    合并）；全未命中/任何异常返回 None 回退占位；
  - `render_env_table`：命中行逐字填、未命中行【待补充】，表后标注来源文档。
- `feishu_client.py`：新增 `read_doc_raw_content`（GET docx raw_content 只读；
  空 id 不发请求，失败/超时降级空串，绝不抛断主链路）。
- `render_report.py`：`_resolve_test_env` 开关守卫（test_env.enabled + 飞书配齐才
  触碰网络）；run 传入 renderer 并落 meta.test_env_filled。
- `renderer.py`：render_report 新增 test_env 参数，2.2 分支填充；未提供时与旧表
  逐字一致。
- 配置接线：`config.py` TestEnvConfig（enabled 默认 False、doc_keywords 默认
  测试环境/账号）、`settings.yaml` test_env 段、`main.py` --test-env 旗标。
- 新测试 `tests/unit/test_env_grounding.py` 14 条（全离线桩）：解析形态/行组不齐
  不填、版本目录不下探、逐份命中即停、异常降级、开关关闭零触碰、渲染逐字一致。
