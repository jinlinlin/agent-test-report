## 需求

§1.3 参考文档中的「需求文档 / 软件用户手册 / UI 设计文档 / 产品原型文档」这类链接，
**同一项目的每个版本都一样**，但飞书「项目+版本」目录未必能自动定位到，此前永远留
【待补充】人工占位。期望：首次由用户提供后按项目登记、之后同项目直接复用；新项目
首次仍须询问。硬约束——**复用一定要是正确的**：严格按项目隔离，绝不跨项目借用。

## 改动

- `report_agent/memory/doc_links.py`（新增）：`DocLinkStore` 本地 JSON 小抄。
  - key = `_norm_project(product)`（小写 + 压缩空白），同项目不同写法收敛一格、
    不同项目硬隔离；`lookup` 未命中一律返回 `None`，无全局默认兜底。
  - `register` 前 `_is_valid_url` 仅收带主机名的 http/https，非法不入库；命中即覆盖。
  - 文件缺失 / JSON 损坏 / 单条记录非法均静默降级为空，不抛断上层。
- `report_agent/memory/__init__.py`（新增）：模块说明。
- `report_agent/config.py`：新增 `MemoryConfig`（`doc_links_enabled` 默认 False、
  `dir`、`doc_links_file`）+ `Config.doc_links_path` 属性 + load 解析。
- `config/settings.yaml`：新增 `memory:` 段（三键，默认关）。
- `.gitignore`：忽略仓库根数据目录 `/memory/`。**关键坑**：不能写 `memory/`，
  否则会连带忽略代码目录 `report_agent/memory/`，导致源码静默脱离版本管理。
- `report_agent/agent/loop.py`：新增惰性 `_doc_store()` 与
  `_resolve_project_doc_links(product_name, state)`——命中复用、未命中且有 `ask`
  入口则首次询问并登记（非法 URL 拒登）；在 `_exec_tool` 的 render 分支以
  `version_info["product_name"]`（报告权威名，别名天然收敛）为键注入
  `project_doc_links`。开关关 / 无产品名返回 `{}`，连 store 实例都不建。
- `report_agent/tools/render_report.py`：`run()` 收 `project_doc_links`，合并
  `{**记忆, **飞书实检}`（同键飞书事实优先）。
- `report_agent/report/templates.py`：`reference_doc_table` 改为任意行只要 ref_links
  带 url 即渲染为链接；无 url 时大纲/用例给「未找到」占位、其余给【待补充】
  （无 ref_links 时行为逐字不变）。
- `report_agent/main.py`：`interactive_clarify` 或 `doc_links_enabled` 任一开启即接
  `_terminal_ask`；新增 CLI 旗标 `--doc-memory`。
- `tests/unit/test_doc_links_memory.py`（新增 13 例）：存取、项目隔离、归一化收敛、
  URL 校验、覆盖、持久化、损坏降级。
- `tests/unit/test_doc_links_render.py`（新增 10 例）：渲染合并、飞书事实优先、
  开关关零触碰、命中复用、项目隔离、首次询问登记、非法不入库。
