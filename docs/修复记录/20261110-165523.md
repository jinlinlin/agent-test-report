## 说明

本次提交合并两部分工作（飞书 V2 脚手架为上一阶段落地、此前尚未入库）：

**一、飞书知识库自动推送（V2）**
- 新增 `feishu_client.py`：tenant_access_token 认证、Drive 上传(`upload_all`) + 导入(`import_tasks`) + 知识库移入。个人版实测 `move_docs_to_wiki` 为异步接口，只落知识库根节点，故走三步：移入库 → 按 obj_token 轮询定位节点 → `move` 到目标父节点。
- 新增 `push_feishu.py`：把渲染好的 Markdown 报告导入为云文档并写入知识库节点，返回文档链接；纯确定性调用，任何失败返回 `ok=False`。
- `loop.py`/`main.py`/`planner.py`/`state.py`/`termination.py`：接入 `push_feishu` 步骤与门控（`--push-feishu`/`feishu.enabled`），推送失败记为 `feishu_error` 且**非致命**——保留已生成报告，不推翻主链路结果为 failed。
- `scripts/feishu_wiki_probe.py`：知识库节点/space 反查排障脚本。

**二、多项目取数与落点路由**
- 产品识别不再用正则猜：`zentao_client.find_product` 运行时拉 `/products`，把**真实产品名**归一化后在整句输入里做包含匹配（最长命中）；`_all_products` 运行内缓存，同一次运行只拉一次；`get_version_bugs` 复用上游 `version_info` 的 product_id+build，不重复取数。
- 新增 `extract_build`（取"含点号数字的非空格 token 连同紧邻前缀"），`parse_version` 基于其重写，兼容 `V5.1.0` / `理工1.0.0`（中文前缀）/ `6.6.7.2`（多段），修复"产品名与版本被空格分开、版本带中文前缀"时产品名丢失、build 只剩数字段的缺陷。
- `zentao_version`/`zentao_bugs`/`loop`：`get_version_info` 接收注入的 `user_input` 解析产品并携带 `product_name`；识别不到产品回退 `default_product`。
- 飞书按项目落点：`feishu_client.find_child_by_title` + `push_feishu._resolve_parent`，在 `wiki_projects_parent` 容器下按产品名路由同名子节点，未命中回退 `wiki_parent_node`，两者皆无记非致命错误。
- 配置：`settings.yaml`/`config.py` 新增 `zentao.default_product`、`feishu.wiki_projects_parent`（含 `.env` 环境变量覆盖）；`.env.example` 补示例。真实凭据与各 token 仍只存本地 `config/.env`（已 gitignore，不入库）。

**已知后续项（本次未改）**：报告标题/文件名取自 `version_info["name"]`（= 正则抽取的 `version_name`），多项目场景下标题未包含产品名（如"理工1.0.0 测试报告"缺"一表通项目"）；已定位成因，待确认后单独修正为"产品名 + 版本"展示名。

**测试**：新增 `tests/unit/test_push_feishu.py` 及 `test_zentao_live.py` 多项目用例（extract_build / CJK 前缀 / find_product 名称匹配 / version_info 复用 / 飞书路由）；`pytest` 全绿 **50 passed**，无回归。
