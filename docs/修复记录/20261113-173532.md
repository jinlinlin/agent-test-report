## 背景与决策

- 用户反馈：2.1 表模块列过宽、描述列疯狂换行；进一步发现**同步到飞书的文档列宽完全没变**。
- 探针实测钉死根因：飞书 docx 导入把 `column_width` 重置为全表等宽默认值，md 分隔行 dash
  比例只影响本地 docx 的 `tblGrid`，到飞书侧被丢弃——与当初"pandoc 底纹被丢弃需块 API 补打"
  同类问题。
- 列宽写入通道逐错试出：`batch_update` 不支持 `update_table_property`（code=1770001）→
  单块 PATCH 传 `column_width` 数组（code=9499）→ 最终**单块 PATCH 逐列设置**
  （`column_index` + 单个整数宽度，px 最小 50）可用。
- 版式匹配按首行表头文字（关键词组 + 列数双条件），未命中版式的表（如 3.2 测试时间）不动；
  总宽取飞书正文列宽实测 660px 按占比拆分。
- 表头样式同期重构：格内文本块背景色（高亮条形态）被否决，改为飞书内置 `header_row` 标记，
  颜色为内置不可指定但整格填满。
- 修复过程中的临时探针 `scripts/_tmp_table_width_probe.py`、`scripts/_tmp_verify_header_row.py`
  已按"用完即删"清理，能力全部正式落地于 feishu_client + push_feishu。
